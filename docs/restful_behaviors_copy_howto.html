Copy SendHttpRequest into your workspace

SendHttpRequest is a MoveIt Pro Behavior that sends one HTTP request (GET, POST, PUT, PATCH or DELETE) to a REST API and puts the response on the blackboard.

Use it when an Objective must talk to a system that does not use ROS: a fleet manager, a job server, a PLC gateway or a dashboard. You do not write C++ for each system. This page tells you how to copy the Behavior from this repository into your own MoveIt Pro workspace, step by step.

Tested. The package files in steps 1 to 6 were built and run on MoveIt Pro 10.1.0, in a copy of the example workspace with a mock robot config. The same package also compiles on MoveIt Pro 9.4.3. The example Objective in step 9 ran unchanged against a local test server.

What you need

  • A MoveIt Pro user workspace that builds with moveit_pro build user_workspace.
  • A robot config package in that workspace (the package you start with moveit_pro run -c).
  • A clone of this repository, to copy two files from.
  • libcurl, the HTTP library. It is already in the MoveIt Pro image. Its rosdep key is libcurl-dev; the build installs it if it is missing.

1Make the package folder

Make a new ROS package called restful_behaviors in your workspace. At the end it has these files:

folder layout
your_ws/src/restful_behaviors/
├── package.xml
├── CMakeLists.txt
├── restful_behaviors_plugin_description.xml
├── include/experimental_behaviors/restful_behaviors/
│   └── send_http_request.hpp        <- copied, keep this path
└── src/
    ├── send_http_request.cpp        <- copied
    └── register_behaviors.cpp       <- new, registers the Behavior

Keep the header in include/experimental_behaviors/restful_behaviors/. The source file includes it by that path, so you do not have to edit the copied files.

2Copy the two source files

shell
# From a clone of moveit_pro_experimental_behaviors (branch with SendHttpRequest):
SRC=~/moveit_pro_experimental_behaviors
PKG=~/your_ws/src/restful_behaviors

mkdir -p $PKG/src $PKG/include/experimental_behaviors/restful_behaviors
cp $SRC/include/experimental_behaviors/restful_behaviors/send_http_request.hpp \
   $PKG/include/experimental_behaviors/restful_behaviors/
cp $SRC/src/restful_behaviors/send_http_request.cpp $PKG/src/

3Add package.xml

This tells the build which packages restful_behaviors needs. Change the maintainer to you.

your_ws/src/restful_behaviors/package.xml
<?xml version="1.0" encoding="utf-8" ?>
<package format="3">
  <name>restful_behaviors</name>
  <version>0.1.0</version>
  <description>REST request Behavior (SendHttpRequest) for MoveIt Pro</description>

  <maintainer email="you@example.com">Your Name</maintainer>

  <license>BSD-3-Clause</license>

  <buildtool_depend>ament_cmake</buildtool_depend>
  <build_depend>moveit_pro_package</build_depend>

  <depend>libcurl-dev</depend>
  <depend>libexpected-dev</depend>
  <depend>moveit_pro_behavior_interface</depend>
  <depend>pluginlib</depend>

  <export>
    <build_type>ament_cmake</build_type>
  </export>
</package>

4Add CMakeLists.txt

This builds one library from the two source files and links libcurl to it.

your_ws/src/restful_behaviors/CMakeLists.txt
cmake_minimum_required(VERSION 3.22)
project(restful_behaviors CXX)

find_package(moveit_pro_package REQUIRED)
moveit_pro_package()

set(THIS_PACKAGE_INCLUDE_DEPENDS moveit_pro_behavior_interface pluginlib)
foreach(package IN ITEMS ${THIS_PACKAGE_INCLUDE_DEPENDS})
  find_package(${package} REQUIRED)
endforeach()
find_package(tl-expected REQUIRED)
find_package(CURL REQUIRED)

add_library(restful_behaviors SHARED src/send_http_request.cpp
                                     src/register_behaviors.cpp)
target_include_directories(
  restful_behaviors PUBLIC $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
                           $<INSTALL_INTERFACE:include>)
ament_target_dependencies(restful_behaviors PUBLIC
                          ${THIS_PACKAGE_INCLUDE_DEPENDS})
target_link_libraries(restful_behaviors PUBLIC tl::expected)
target_link_libraries(restful_behaviors PRIVATE CURL::libcurl)

install(
  TARGETS restful_behaviors
  EXPORT restful_behaviorsTargets
  ARCHIVE DESTINATION lib
  LIBRARY DESTINATION lib
  RUNTIME DESTINATION bin
  INCLUDES
  DESTINATION include)

pluginlib_export_plugin_description_file(
  moveit_pro_behavior_interface restful_behaviors_plugin_description.xml)

ament_export_targets(restful_behaviorsTargets HAS_LIBRARY_TARGET)
ament_export_dependencies(${THIS_PACKAGE_INCLUDE_DEPENDS} tl-expected)
ament_package()

5Add the loader

A loader is a small class that MoveIt Pro calls at start-up. It registers the Behavior under the name you use in Objectives (SendHttpRequest). The plugin description file tells MoveIt Pro where the loader is.

your_ws/src/restful_behaviors/src/register_behaviors.cpp
#include <behaviortree_cpp/bt_factory.h>
#include <moveit_pro_behavior_interface/behavior_context.hpp>
#include <moveit_pro_behavior_interface/shared_resources_node_loader.hpp>

#include <experimental_behaviors/restful_behaviors/send_http_request.hpp>

#include <pluginlib/class_list_macros.hpp>

namespace restful_behaviors
{
class RestfulBehaviorsLoader : public moveit_pro::behaviors::SharedResourcesNodeLoaderBase
{
public:
  void registerBehaviors(BT::BehaviorTreeFactory& factory,
                         const std::shared_ptr<moveit_pro::behaviors::BehaviorContext>& shared_resources) override
  {
    moveit_pro::behaviors::registerBehavior<experimental_behaviors::SendHttpRequest>(factory, "SendHttpRequest",
                                                                                     shared_resources);
  }
};
}  // namespace restful_behaviors

PLUGINLIB_EXPORT_CLASS(restful_behaviors::RestfulBehaviorsLoader, moveit_pro::behaviors::SharedResourcesNodeLoaderBase);
your_ws/src/restful_behaviors/restful_behaviors_plugin_description.xml
<?xml version="1.0" encoding="utf-8" ?>
<library path="restful_behaviors">
  <class
    type="restful_behaviors::RestfulBehaviorsLoader"
    base_class_type="moveit_pro::behaviors::SharedResourcesNodeLoaderBase"
  />
</library>

6Load the loader in your robot config

Add the loader under objectives: behavior_loader_plugins: in the config.yaml of the robot config you run. Use a key that no other entry uses. If your config has a parent (based_on_package), the entries merge, so the core Behaviors stay loaded.

your_robot_config/config/config.yaml
objectives:
  behavior_loader_plugins:
    restful_behaviors:
      - "restful_behaviors::RestfulBehaviorsLoader"
  # ...your other objectives settings stay as they are

Also add a run-time dependency, so the build and install order is correct:

your_robot_config/package.xml
<!-- In your robot config package's package.xml -->
<exec_depend>restful_behaviors</exec_depend>

7Build

shell
moveit_pro build user_workspace
# Look for:  Finished <<< restful_behaviors

8Start MoveIt Pro and check

shell
moveit_pro run -c <your_config_package>
# In the runtime log, the loader list includes your loader:
#   Loading 5 behavior loader plugin(s):
#     ...
#     restful_behaviors::RestfulBehaviorsLoader

In the Objective editor, SendHttpRequest is in the Behavior list under REST.

9Try the example Objective

Save this as an XML file in your config's Objectives folder. It reads job 42 from a job server, marks it done, and writes the status code to the log. Change http://127.0.0.1:8080 to your server.

your_robot_config/objectives/rest_example.xml
<?xml version="1.0" encoding="UTF-8" ?>
<root BTCPP_format="4" main_tree_to_execute="REST Example">
  <!-- Reads a job from a REST API, reports progress, and logs the reply -->
  <BehaviorTree
    ID="REST Example"
    _description="Reads job 42 from a REST API, marks it done, and logs the status code"
  >
    <Control ID="Sequence">
      <!-- GET http://127.0.0.1:8080/api/jobs?id=42 with an API key header -->
      <Action
        ID="SendHttpRequest"
        url="http://127.0.0.1:8080/api/jobs"
        method="GET"
        query_parameters='{"id": "42"}'
        headers='{"Accept": "application/json", "X-Api-Key": "my-key"}'
        timeout="5.0"
        status_code="{job_status}"
        response_body="{job}"
        response_headers="{job_headers}"
        error_message="{job_error}"
      />
      <!-- PUT a JSON body; content_type defaults to application/json -->
      <Action
        ID="SendHttpRequest"
        url="http://127.0.0.1:8080/api/jobs/42"
        method="PUT"
        body='{"state": "done"}'
        status_code="{update_status}"
      />
      <!-- status_code is an int: make a text copy before a string port uses it -->
      <Action
        ID="Script"
        code="report := 'Job server answered HTTP ' .. update_status"
      />
      <Action ID="LogMessage" message="{report}" />
    </Control>
  </BehaviorTree>
  <TreeNodesModel>
    <SubTree ID="REST Example">
      <MetadataFields>
        <Metadata subcategory="REST" />
      </MetadataFields>
    </SubTree>
  </TreeNodesModel>
</root>

status_code is an int, so status_code == 200 works in a Script. A string port cannot use the same blackboard key, so the example makes a text copy first:

status code as text
<Action ID="Script" code="report := 'Server answered HTTP ' .. status_code"/>
<Action ID="LogMessage" message="{report}"/>

Ports

JSON on a port is always text in a std::string. A 2xx status is SUCCESS. Any other status, or no response, is FAILURE; all four outputs are still written. The full rules are in docs/restful_behaviors.md.

PortDirTypeDefaultMeaning
urlinstringhttp:// or https:// address
methodinstringGETGET, POST, PUT, PATCH or DELETE
query_parametersinstring""JSON object as text, e.g. {"id": "42"}
headersinstring""JSON object as text, e.g. {"Accept": "application/json"}
bodyinstring""Sent as it is. Must be empty for GET
content_typeinstringapplication/jsonContent-Type of the body
timeoutindouble10.0Seconds for the whole request
verify_tlsinbooltrueCheck the https certificate
follow_redirectsinboolfalseFollow 3xx redirects
status_codeoutint{status_code}0 if there was no response
response_bodyoutstring{response_body}Response body
response_headersoutstring{response_headers}JSON object, lower-case names
error_messageoutstring{error_message}Empty on SUCCESS

Another way: add it to a package you already have

If your workspace already has a Behavior package with its own loader, you can add SendHttpRequest to it instead of making a new package. (This path was not run end to end; the new-package path above was.)

changes in your existing Behavior package
# 1. Copy the two files into your package (same folders as in step 2).
# 2. CMakeLists.txt of your package:
find_package(CURL REQUIRED)
#    add src/send_http_request.cpp to your add_library(...) source list, then:
target_link_libraries(<your_library> PRIVATE CURL::libcurl)
# 3. package.xml:  <depend>libcurl-dev</depend>
# 4. In your loader's registerBehaviors(...):
#    moveit_pro::behaviors::registerBehavior<experimental_behaviors::SendHttpRequest>(
#        factory, "SendHttpRequest", shared_resources);
#    and add:  #include <experimental_behaviors/restful_behaviors/send_http_request.hpp>
Security. HTTP sends in clear text, so use https:// on networks you do not control. Keep verify_tls true unless the server is a trusted device with a self-signed certificate. A token typed into headers is stored in the Objective file; prefer a blackboard value. Check every field of a response before it drives motion.

If something goes wrong

The Objective does not load: port [x] was initially created with type [int] and, later type [std::string]

status_code is an int. A string port (for example LogMessage message) cannot use the same blackboard key. Make a text copy with a Script first (see step 9).

CMake error: Could not find a package configuration file provided by "CURL"

Add <depend>libcurl-dev</depend> to package.xml. moveit_pro build runs rosdep, which installs it.

SendHttpRequest is not in the Behavior list

The loader is not loaded. Check the behavior_loader_plugins entry in config.yaml (step 6) and the loader name in restful_behaviors_plugin_description.xml. They must match restful_behaviors::RestfulBehaviorsLoader.

error_message says SSL certificate problem

The server uses a certificate your system does not trust, for example a self-signed one. On a network you control, set verify_tls="false". Otherwise install the CA certificate in the image.

A literal like {abc} in body is read as a blackboard key

BT.CPP reads text in braces as a blackboard key. Text that is valid JSON, such as {"a": 1}, is sent as it is. Other text in braces must come from the blackboard.

Source of truth: src/restful_behaviors/send_http_request.cpp and docs/restful_behaviors.md in this repository.
